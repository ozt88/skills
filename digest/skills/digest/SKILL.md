name: digest
description: Turn a long document the user is reading (Notion page, web article, docs site, PDF, local file, or pasted text) into a layered Korean digest that can be absorbed quickly - one line, a 3-line TL;DR, key points, a section map that says which parts are worth reading in the original, and what is left for the reader - shown in chat, or drawn as a foldable inline widget on request. Use when the user shares a Notion or web link or a long text and says digest, 다이제스트, 소화, 요약, 정리, "핵심만", "읽기 좋게", or that a document is too long to read. Do not use for writing new documents or editing the source.

# digest

길어서 읽기 힘든 문서를 위에서부터 읽다가 어디서 멈춰도 되는 형태로 바꾼다.
원문은 읽기만 한다. 원문 페이지나 파일은 고치지 않는다.

## 1. 원문 가져오기

원문은 끝까지 읽는다. 앞부분만 읽고 만든 digest는 결론을 놓친다.

| 원문 | 가져오는 방법 |
|---|---|
| 노션 링크나 페이지 ID | `notion-page` 스킬로 본문을 읽는다. 실패하면 Notion MCP의 fetch를 쓴다 |
| 웹 링크 | WebFetch를 쓰고, prompt에 "요약하지 말고 본문을 제목 구조와 함께 그대로 돌려줘"라고 적는다. 잘리면 offset으로 이어 읽는다 |
| 로그인이 필요하거나 스크립트로 그리는 웹 페이지 | 내장 브라우저로 열고 `get_page_text`로 읽는다 |
| 로컬 파일, PDF | Read로 읽는다. PDF는 20쪽씩 나눠 읽는다 |
| 붙여넣은 글 | 그대로 쓴다 |

- 노션 하위 페이지와 연결된 데이터베이스는 따라가지 않는다. 제목만 모아 "더 볼 거리"에 둔다.
  사용자가 하위 페이지까지 포함하라고 하면 그때 읽는다.
- 끝까지 읽지 못했으면(권한, 잘림, 오류) digest 맨 위에 어디까지 읽었는지 적는다.

### 노션 본문 이미지

분석 문서는 수치가 본문보다 차트 이미지에 더 많이 들어 있다. 본문에 `<image source="notion-file-block://...">`가 있으면 내려받아 읽는다.

1. 이미지의 `notion-file-block://` 참조를 원문 그대로 모아 Notion MCP의 `get_file_download_urls`에 넘긴다(한 번에 25개까지).
   받은 URL은 5분 뒤 만료되니 받자마자 바로 내려받는다. 만료됐으면 다시 받는다.
2. 세션 scratchpad 디렉터리(없으면 OS 임시 디렉터리) 아래에 빈 하위 디렉터리를 만들고 `curl`로 내려받는다.
   파일 이름은 본문에 나온 순서대로 `1.png`, `2.png`처럼 붙인다. HTTP 상태가 200인지 확인한다.
   한 번에 받은 URL들은 쿼리 문자열이 `X-Amz-Signature` 값만 빼고 같다. 같은 부분은 변수로 한 번만 적어서 옮겨 적다 틀리는 것을 줄인다.
3. Read로 이미지를 연다. 이미지 바로 위아래 본문과 짝지어 읽는다.

- 아이콘, 로고, 장식용 이미지는 건너뛴다. 이미지가 10개를 넘으면 본문 설명으로 보아 데이터가 있는 것만 읽는다.
- 차트에서 읽은 수치는 digest에 그대로 쓰되, 본문에 없는 수치는 처음 나올 때 `(차트)`를 붙인다.
- 본문 수치와 차트 수치가 다르면 둘 다 적고 어긋난다고 표시한다. 어느 쪽이 맞는지 정하지 않는다.
- 읽지 못한 이미지가 있으면 digest 맨 위에 몇 개를 못 읽었는지 적는다.

## 2. 읽는 목적

사용자가 목적을 말했으면("우리 팀에 적용할 부분만", "결정된 것만") 그 목적에 맞는 내용을 앞에 두고,
관계없는 섹션은 구조 지도에서 한 줄로 줄인다. 목적을 말하지 않았으면 묻지 않고 일반 digest를 만든다.

## 3. 분량에 따라 나누기

- 원문이 3천 자 이하면 한 줄과 TL;DR, 핵심 내용만 쓴다. 글자 수에는 이미지를 넣지 않는다.
  차트가 여럿인 분석 문서는 짧아도 구조 지도를 쓴다.
- 3만 자 이하면 직접 처리한다.
- 그보다 길면 원문을 제목 단위로 3~6덩이로 나눠 서브에이전트에 맡긴다. 프롬프트는 한국어로 쓰고,
  덩이마다 다음을 돌려받는다: 섹션별 요약 1~2줄, 핵심 주장과 근거, 결정 사항과 할 일, 낯선 용어.
  합칠 때 겹치는 내용은 하나로 줄이고, 덩이 사이에서 앞뒤가 맞지 않는 주장은 그대로 드러낸다.

## 4. digest 형식

아래 순서로 쓴다. 해당 내용이 없는 절은 뺀다.

```md
# <원문 제목>

원문: <링크 또는 경로> | 약 N자, 원문 읽는 데 약 M분

> <한 줄: 이 문서가 결국 무엇을 말하는지>

## TL;DR
- 3줄 이내

## 핵심 내용
1. **<주장>**: 근거나 맥락 한 줄
   (3~7개)

## 구조 지도
| 섹션 | 내용 | |
|---|---|---|
| <원문 섹션 제목> | 1~2줄 | ⭐ 원문으로 읽기 |

## 용어
- **<용어>**: 이 문서에서 쓰는 뜻

## 나에게 남는 것
- 결정된 것 / 할 일 / 열린 질문 / 문서가 다루지 않은 것

## 더 볼 거리
- 하위 페이지, 본문에 걸린 중요한 링크
```

- 읽는 시간은 한국어 분당 500자, 영어 분당 230단어로 셈한다.
- ⭐는 요약으로 대신하기 어려운 섹션에만 단다. 표, 코드, 세부 절차, 논증이 촘촘한 부분이 해당된다.
- 용어는 사용자가 모를 만한 것만 적는다. 일반 개발 용어는 넣지 않는다.

### 쓰는 원칙

- 원문에 없는 내용을 지어내지 않는다. 내 해석을 덧붙여야 하면 문장 끝에 `(해석)`을 단다.
- 숫자, 날짜, 이름, 고유명사는 원문 그대로 옮긴다.
- 비중은 분량이 아니라 중요도로 정한다. 결론, 결정, 바뀐 점, 반대 의견을 배경 설명보다 앞에 둔다.
- 원문이 영어여도 digest는 한국어로 쓴다. 용어는 처음 나올 때 원어를 괄호에 함께 적는다.
- 원문 표현 자체가 중요하면 짧게 인용한다. 문단을 통째로 옮기지 않는다.

### 문체

- 문장은 합니다체로 쓴다. "늘었다", "줄었음"처럼 한다체나 음슴체로 끝나는 문장을 섞지 않는다.
  표 칸, 라벨, 배지처럼 짧은 글만 명사구로 끝낸다.
- 추상 명사로 압축하지 않고 무엇이 어떻게 됐는지 쓴다.
  "풀 분리의 비용은 PvPvE 쪽에만 생겼다"가 아니라 "매칭이 나빠진 곳은 PvPvE 풀뿐입니다"로 쓴다.
- 수치에는 단위(건, 초, %, %p)를 붙이고, 무엇의 수치인지 문장이나 라벨에 밝힌다.
- 엠대시(`—`)와 가운뎃점(`·`)을 쓰지 않는다. 조사는 영단어, 숫자, 괄호 뒤에도 붙여 쓴다.
- `ko-dev-style` 스킬을 쓸 수 있으면 내보내기 전에 그 점검을 거친다.

## 5. 내보내기

기본은 채팅에 그대로 보여 준다. 사용자가 시각화를 원하면 위젯으로 그린다.

- **위젯**: "시각화해줘", "위젯으로", "한눈에 보게" 같은 요청에 `show_widget`으로 그린다. [widget.md](widget.md)의 구성, 글꼴, 문체 기준을 따른다.
  차트가 2개 이상이거나 비교할 수치가 많은 문서는 채팅 digest 끝에 위젯으로 볼지 한 줄로 묻는다.
  `show_widget` 도구가 없는 환경이면 위젯을 쓸 수 없다고 말하고 채팅 digest로 마친다.

사용자가 저장하라고 하면 다음처럼 한다.

- **노션**: `notion-page` 스킬로 새 페이지를 만든다. 위치를 말하지 않았으면 어디에 둘지 묻는다.
  원문 페이지 안에 쓰거나 원문을 고치지 않는다.
- **파일**: 현재 작업 디렉터리의 `digests/<원문 제목 슬러그>.md`에 쓴다.

## 6. 이어지는 질문

digest를 본 뒤 특정 부분을 물으면 이미 가져온 원문에서 답하고, 답의 근거가 원문 어느 섹션인지 함께 적는다.
원문에 없는 내용이면 없다고 말한다.
