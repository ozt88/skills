Before its next action, the session writes a request (facts and material paths, apart from its plan); a fresh agent checks the plan's assumptions against the material and returns an intervention memo - keep, revise, or replace, broken assumptions, one out-of-frame alternative with file:line evidence, next actions, and switch conditions. # noclip: 세션이 기대는 벽을 통과해 보기

진행 중인 세션은 자기가 고른 틀 안에서 다음 행동을 정한다. 그 틀을 받치는 가정(벽)은 세션 안에서 잘 보이지 않는다.
noclip은 세션이 다음 행동을 정하기 직전에 새 에이전트를 띄워, 현재 계획이 기대는 가정을 자료로 확인하고 틀 밖 대안 하나를 개입 메모로 돌려받는다.
문제를 처음부터 다시 푸는 스킬이 아니다. "지금 하려는 것 말고 이것을 보라"를 건네는 스킬이다. 결정은 사용자가 한다.

## 1. 언제 부르나

- 사용자가 `/noclip`을 부르거나 "지금 방향 밖에서 봐 줘"처럼 요청하면 바로 2절부터 한다.
- 세션이 먼저 제안하는 경우는 아래 셋뿐이다.
  - 비싸거나 되돌리기 어려운 실행 직전(긴 실험, 대량 변경, 배포, 데이터 삭제 등)
  - 같은 문제를 두 번 넘게 고치고 있을 때
  - 결과가 기대와 다를 때
- 제안은 한 줄로 하고, 사용자가 승인해야 실행한다. 작은 일상 변경에는 제안하지 않는다.

## 2. 요청서

세션이 실행 폴더 `.noclip/<YYYY-MM-DD>-<짧은 이름>/`을 만들고 `request.md`를 쓴다. `사실`과 `현재 계획`을 나눠 쓴다.
짧은 이름은 다루는 문제로 짓고(예: `report-timeout`), 계획 내용(예: `try-policy-c`)을 담지 않는다. 폴더 이름은 좌석에도 보이기 때문이다.

```
# noclip 요청서

## 사실
- 목표: 사용자가 원하는 것. 사용자 말 그대로 쓰고 출처(문서 경로, 요청 시점)를 단다
- 지금까지 시도와 결과: 무엇을 해서 무엇이 나왔나. 수치, 명령, 파일 경로를 단다
- 정해진 제약과 결정: 바꾸면 안 되는 것과 그 출처
- 자료 경로: 에이전트가 직접 열 파일, 디렉터리, 명령. 열면 안 되는 곳도 적는다

## 현재 계획
- 다음 행동: 세션이 지금 하려는 것
- 이유: 왜 그것을 고르려 하는가
```

- 세션 대화 기록은 넘기지 않는다. 대화에 깔린 틀이 함께 넘어가기 때문이다. 대화에만 있는 사실은 `사실`에 옮겨 적는다.
- `사실`에 해석이나 계획을 섞지 않는다. "X가 원인이다"가 아니라 "X를 바꾸자 Y가 나왔다"로 쓴다.
- 자료는 요약하지 않고 경로를 준다. 에이전트가 스스로 연다.
- 현재 계획을 담은 파일과 디렉터리(계획 문서, TODO, 작업 메모, `.checkpoint/` 같은 작업 원장)는 자료 경로에 넣지 않고, "열면 안 되는 곳"에 적는다. 좌석 모드에서 계획이 좌석에 새는 길이 된다.

## 3. 빠른 모드 (기본)

- 새 서브에이전트 하나를 띄운다. 이 스킬의 절차는 Claude Code 기준이다. Agent 도구 `subagent_type: "general-purpose"`를 쓰고, `fork`는 대화 맥락을 물려받으므로 쓰지 않는다.
- 프롬프트는 [references/fast.md](references/fast.md)의 블록 원문에 `{run}`과 `{memo}`를 채우고, 끝에 5절의 메모 형식 블록을 붙인다. `{memo}`는 빠른 모드만 돌리면 `memo.md`, 짝 실행이면 `memo-fast.md`다. 세션은 요약이나 의견을 덧붙이지 않는다.
- 에이전트는 요청서의 자료 경로를 스스로 열고 `{memo}`에 메모를 쓴다.
- 보통 2~4분, 1~2 USD 안팎이다.

## 4. 좌석 모드 (실험판)

- 사용자가 "좌석 모드", "seats"처럼 직접 이름을 댈 때만 쓴다. 세션이 먼저 고르거나 권하지 않는다.
- 부르기 전에 사용자에게 알리고 승인을 받는다.
  - 좌석 모드만으로 1회 5~10 USD, 15~30분 안팎이 든다. 같은 요청서로 빠른 모드도 함께 돌리므로(짝 실행) 1~2 USD가 더 들고, 빠른 모드는 좌석 모드가 끝나기 전에 끝난다.
  - 실험판인 이유: 작은 비교에서 빠른 모드보다 낫다는 근거가 나오지 않았다. 짝 기록으로 계속 판정한다.
- 절차는 [references/seats.md](references/seats.md)와 [references/judge.md](references/judge.md)를 따른다. 요점은 아래와 같다.
  - 좌석마다 서로 다른 출발 가설, 금지 구역, 탐색 시작점, 성공 조건을 주고, 좌석이 자료를 직접 탐색해 근거를 봉인한다. 교환 1회 뒤 Judge가 메모를 쓴다.
  - **현재 계획은 기본 답 자리에 두고 좌석에 전하지 않는다.** 세션(조정자)과 Judge만 본다. 좌석이 계획을 보면 그 계획을 보완하는 결론을 내기 쉽다. 좌석에는 요청서의 `사실`만 간다.
  - **짝 실행**: 좌석을 띄울 때 빠른 모드 에이전트도 같은 `request.md`로 함께 띄운다. 결과는 `memo-fast.md`와 `memo-seats.md`다. 두 쪽은 서로의 결과를 보지 않는다.

## 5. 개입 메모 형식

두 모드가 같은 형식을 쓴다.

```
# 개입 메모: {현재 계획의 다음 행동 한 줄}

## 판정: {유지 | 수정 | 교체}
{한 줄 이유. 근거 파일:줄}

## 깨진 가정
현재 계획이 기대는 가정 중 자료로 깨진 것. 가정마다 한 줄: 가정 / 깨뜨린 사실 / 근거(파일:줄)
깨진 것이 없으면 "없음"과, 확인해서 성립한 가정 목록

## 틀 밖 대안
- 안: 현재 계획의 틀 밖에 있는 안 하나
- 근거: 파일:줄
- 대가: 이 안을 하면 같이 해야 하는 일, 비용, 부작용

## 다음 행동
1. 지금 할 행동. 1~3개, 순서대로

## 지켜야 할 것
- 자료로 받쳐진 진단, 의무, 금지를 한 줄씩. 형식: `[진단 | 의무 | 금지] 항목 (근거 파일:줄)`
- 현재 계획 쪽에서 나온 항목이어도 근거가 있으면 같은 강도로 남긴다

## 전환 조건
- {확인할 사실}이 확인되면 {다른 안}으로 바꾼다. 확인 방법: {볼 파일, 돌릴 명령, 물을 사람}

## 남은 이견 (있을 때만)
- 확인 방법을 적을 수 없는 쟁점. 사실 확인으로 풀리는 것과 가치 판단을 나눈다
```

- 판정의 뜻
  - 유지: 현재 계획을 그대로 한다. 틀 밖 가설이 모두 자료로 무너졌을 때만 쓴다.
  - 수정: 현재 계획의 일부를 남기되, 다음 행동에 틀 밖 대안의 최선형이나 그 대안을 판가름할 확인 단계가 반드시 들어간다. 현재 계획에 확인 단계만 덧붙이고 틀 밖 대안과 상관없는 것은 수정이 아니라 유지이고, 유지의 조건을 따른다.
  - 교체: 틀 밖 대안을 다음 행동으로 삼는다.
- 유지 판정이어도 틀 밖 대안 칸을 채운다. 그 안을 무너뜨린 반증(파일:줄)을 근거 칸에 적는다.
- 대안은 하나다. 다른 후보는 전환 조건으로 보낸다.
- 다음 행동에는 "A 또는 B", "확인한 뒤 정한다"를 쓰지 않는다. 확인이 필요하면 확인을 한 단계로 넣는다.
- 지켜야 할 것: 자료로 받쳐진 항목은 약하게 만들거나 빼지 않는다. 약하게 만들려면 그 항목을 직접 반증하는 파일:줄이 있어야 한다. 현재 계획과 같다는 것, 틀 밖 대안과 어긋난다는 것, 메모를 짧게 하려는 것은 이유가 되지 않는다. 틀 밖 대안과 충돌하면 남은 이견에 적는다.
- 메모에는 과정의 내부 라벨(가정 번호, 가설 번호, 좌석 ID, 근거 ID)과 과정 용어를 쓰지 않는다. 근거는 원 출처(파일:줄)로 단다.

## 6. 메모를 받은 뒤

- 메모는 계획을 바로 바꾸지 않는다. 세션은 메모를 사용자에게 그대로 보이고, 사용자가 고른다.
- 세션은 자기 계획을 변호하는 말을 메모 앞에 붙이지 않는다. 의견이 있으면 메모 뒤에 "세션 의견"으로 따로 표시한다.
- 짝 실행이면 A, B 배정을 무작위로 정한다(예: `shuf -n1 -e fast seats`로 A를 뽑는다). 배정은 사용자가 채택 표를 채운 뒤에 출처 줄에 적는다. 두 메모를 "메모 A", "메모 B"로 나란히 보이되 파일 이름과 경로는 드러내지 않는다. 어느 쪽이 좌석 모드인지는 사용자가 채택 기록을 마친 뒤에 밝힌다.
- 사용자가 고른 대로 진행하고, 7절의 채택 기록을 쓴다.

## 7. 기록

실행마다 프로젝트 루트의 `.noclip/`에 폴더 하나를 남긴다.

```
.noclip/<YYYY-MM-DD>-<짧은 이름>/
  request.md      세션: 사실 + 현재 계획
  memo.md         빠른 모드 메모 (빠른 모드만 돌렸을 때)
  memo-fast.md    짝 실행의 빠른 모드 메모
  memo-seats.md   짝 실행의 좌석 모드 메모 (좌석 모드가 중간에 멈추면 만들지 않는다)
  seats/          좌석 모드 과정 파일 (references/seats.md). 멈췄으면 멈춘 단계와 이유를 seats/stopped.md에 적는다
  adoption.md     세션: 사용자의 채택 기록
```

`adoption.md` 형식:

```
# 채택 기록
- 날짜:
- 모드: 빠른 모드 / 짝 실행 / 좌석 중단 (짝 실행을 시작했지만 좌석 모드가 멈춘 경우)
- 걸린 시간과 비용: 모드별로, 알 수 있는 만큼
- 사용자 결정: 현재 계획 그대로 / 메모대로 / 일부 반영

| 메모 | 항목 | 결정 | 이유 |
|---|---|---|---|
| A | 판정: 수정 | 채택 / 거절 / 수정 | 사용자가 말한 이유 |

출처: A = {fast | seats}, B = {fast | seats}   (짝 실행이면 표를 채운 뒤에 적는다)

## 나중에 확인한 것
- {날짜}: 전환 조건 "{…}"이 맞았는가 / 틀렸는가
```

- 항목은 판정, 깨진 가정 각각, 틀 밖 대안, 다음 행동 각각, 지켜야 할 것 각각이다.
- 좌석 중단이면 `memo-fast.md` 하나만 "메모 A"로 보이고 출처 줄에 `A = fast`를 적는다. 이 기록은 짝 비교에 넣지 않는다.
- 이유는 사용자 말을 옮긴다. 세션이 이유를 지어내지 않는다. 사용자가 이유를 말하지 않았으면 비워 둔다.
- 짝 기록을 남기는 목적은 좌석 모드를 유지할지 다시 판정하는 것이다. 예를 들어 "좌석 메모에만 있고 사용자가 채택한 항목"이 나온 짝의 비율을 본다. 판정 기준은 기록을 열어 보기 전에 정한다.
- `.noclip/`에는 자료 경로와 작업 사실이 들어간다. 커밋할지는 프로젝트가 정하고, 공개 저장소면 `.gitignore`에 넣는다.

## 8. 하지 않는 것

- 세션 대화 기록을 에이전트나 좌석에 넘기지 않는다.
- 좌석 모드에서 현재 계획을 좌석에 전하지 않는다. 금지 구역이나 돌려보내는 이유로 바꿔 쓰는 것도 같다.
- 메모를 받고 사용자 확인 없이 계획을 바꾸지 않는다.
- 빠른 모드 결과가 마음에 들지 않는다고 좌석 모드를 이어서 돌리지 않는다. 좌석 모드는 사용자가 이름을 댈 때만 쓴다.
- 새 사실 없이 같은 요청서로 다시 돌리지 않는다.
- 비용이나 부작용, 이미 정한 다른 안과 다르다는 이유로 틀 밖 대안을 버리지 않는다. 틀 밖 대안을 버리는 근거는 그 안을 직접 무너뜨린 반증뿐이다.
- 틀 밖 대안을 찾았다고 자료로 받쳐진 기존 제약과 결정을 버리지 않는다. 대안은 그 제약과 결정을 지키는 형태로 낸다.
