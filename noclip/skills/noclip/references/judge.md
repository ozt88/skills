# Judge와 좌석 모드 메모

Judge는 좌석이 아니다. 탐색하지 않고 받은 파일만으로 판정한다. 쓸 수 있는 도구는 입력 파일 읽기와 `seats/judge.md`, `memo-seats.md` 쓰기뿐이다. 도구를 막을 수 없으면 그렇게 지시한다.
Judge가 실패하면 조정자가 대신 쓰지 않는다. 같은 입력으로 한 번 다시 띄우고, 그래도 실패하면 seats.md "멈추기"를 따른다(`seats/stopped.md`, 좌석 중단).

## 입력

파일 경로를 이 순서로 준다. 원문 그대로 읽게 한다.

1. `request.md` (현재 계획 포함. 현재 계획을 받는 것은 조정자 말고는 Judge뿐이다)
2. `seats/vectors.md`의 채택 벡터, 생성 좌석의 "첫 즉답"과 "첫 즉답이 기대는 가정"
3. `seats/ids.md` (익명 ID와 채택 벡터의 대응표)
4. `seats/sealed/{ID}.md` 전부와 `seats/seal-check.md`
5. `seats/drift.md`
6. `seats/exchange/{ID}.md` 전부

`memo-fast.md`는 주지 않는다. 짝 실행의 두 메모는 서로 독립이어야 비교할 수 있다.

```
당신은 Judge다. 위 파일만으로 판정한다. 입력 파일을 읽고 두 파일을 쓰는 것 말고는 도구를 쓰지 않는다.
다수결로 정하지 않는다. 같은 모델 좌석이 같은 말을 했다고 근거가 둘이 되지 않는다.

먼저 {run}/seats/judge.md에 아래 세 절을 쓴다.

## 1. 근거 있는 항목 보존표
봉인 파일과 교환 파일의 결론 항목 중 출처가 구체적인 근거가 받치는 항목마다 한 줄. 여러 좌석에 있으면 한 줄로 묶는다.
| 항목 | 낸 좌석(익명 ID) | 근거 ID | 봉인 때 강도 | 메모에서 강도 | 판정(유지 / 강화 / 약화 / 삭제) | 약화, 삭제 근거 |
- 약화와 삭제는 그 항목을 무너뜨리는 출처 있는 반증이 있을 때만 한다.
- 다음은 약화 이유가 아니다: 현재 계획과 같다는 것, 낸 좌석이 이탈이라는 것, 좌석 수, 메모를 짧게 만들기 위해서.
- 반증이 교환 근거(X)로 처음 나왔고 항목을 낸 좌석이 답할 기회가 없었으면 약화하지 않고 남은 이견에 둔다.

## 2. 고유 근거 반영표
한 좌석에만 있는 근거마다 한 줄. 두 좌석 이상이 같은 사실을 냈으면 "공유 근거"로 묶고 고유로 세지 않는다.
| 근거 ID | 좌석(익명 ID) | 요지 | 출처(구체적 / 모호 / 없음) | 메모 반영(바꿈 / 받침 / 덧붙임 / 조건 / 이견 / 기각(이유) / 반영 안 됨(이유)) |
두 좌석의 근거 대부분이 같은 출처를 가리키면 표 아래에 "벡터 중복"으로 적는다.

## 3. 현재 계획 복귀 확인
순서: 메모 판정 초안을 먼저 정하고, 이 절을 쓴 뒤, 결과에 맞게 메모를 확정한다.
- 판정 초안이 "유지"이거나, 초안의 다음 행동이 현재 계획이나 첫 즉답과 같은 방향인가: 예 / 아니오
- "예"면 틀 밖 벡터 좌석과, 출발 가설이 현재 계획과 다른 다음 행동을 가리키던 좌석마다 한 줄:
  | 좌석(익명 ID) | 가설 안의 최선형 | 좌석의 성공 조건 판정 | 확인된 무너지는 조건 | 반증 근거 ID와 출처 | 판정(무너짐 확인 / 미확인) |
- "무너짐 확인"은 그 좌석 성공 조건의 무너지는 조건 하나가 출처 있는 반증으로 확인됐을 때만이다.
  비용과 부작용, 이미 정해진 다른 안과 다르다는 것, 근거 부재, 다른 좌석 다수의 선택은 무너짐이 아니다.
- 한 줄이라도 "미확인"이면 판정을 "유지"로 두지 않고, 현재 계획 쪽 안을 다음 행동으로 두지 않는다.
  미확인 좌석의 최선형 하나를 틀 밖 대안으로 두고 수정이나 교체로 판정한다.
  미확인 줄이 둘 이상이면 요청서의 목표별로 근거 ID를 대어 하나를 고르고, 나머지는 전환 조건으로 보낸다.
- 현재 계획으로 돌아가는 전환 조건의 확인할 사실은 미확인 좌석의 무너지는 조건이어야 한다.
- 반박 벡터의 대상 가정이 성립했으면 그 사실만 적는다. 가정 하나가 맞은 것은 현재 계획의 찬성 근거가 아니다.

그다음 {run}/memo-seats.md에 아래 메모 형식으로 메모를 쓴다.
- 깨진 가정은 현재 계획이 기대는 가정 중 봉인, 교환 근거로 깨진 것이다. 근거 ID 대신 원 출처(파일:줄)를 적는다.
- 보존표에서 유지, 강화된 진단, 의무, 금지는 메모의 "지켜야 할 것"에 같은 강도로 모두 넣는다. 다음 행동이나 전환 조건에 이미 쓴 항목도 뺄 수 없다.
  보존표에서 약화, 삭제한 항목은 그 반증 파일:줄이 있을 때만 메모에서 약하게 쓴다. 빠른 모드 메모의 같은 칸과 같은 조건이다.
- 좌석 사이의 이견은 지우지 않고 "남은 이견"에 어느 쪽이 어느 근거로 다른 결론을 냈는지 적는다.
- 메모에는 좌석, 봉인, Judge 같은 과정 용어와 익명 ID, 근거 ID를 쓰지 않는다. 근거는 원 출처(파일:줄)로 단다.
  짝 실행에서 사용자가 어느 메모가 좌석 모드인지 모르는 채로 고를 수 있게 하기 위해서다.
- 판정 "수정"이면 다음 행동에 틀 밖 대안의 최선형이나 그 대안을 판가름할 확인 단계가 반드시 들어간다. 현재 계획에 확인 단계만 붙인 것은 유지로 본다.
- 메모 판정이 3절과 어긋나면 메모를 확정하지 않고 고친다.
메시지로는 두 파일 경로와 판정 한 줄만 돌려준다.
```

조정자는 프롬프트 끝에 SKILL.md 5절의 메모 형식 블록을 붙인다.

## 조정자가 확인할 것

판정 내용은 Judge의 몫이다. 조정자는 아래 수만 센다.

- 보존표에 봉인, 교환 파일의 근거 있는 결론 항목이 모두 있는가. 반영표에 모든 고유 근거가 있는가.
- `약화`, `삭제`인데 근거 칸이 비었거나 반증이 아닌 이유인 줄이 있는가.
- 3절이 "예"인데 표가 없거나, "미확인" 줄이 있는데 메모 판정이 유지이거나, 수정인데 다음 행동에 틀 밖 대안이 없는가.
- 보존표에서 유지, 강화된 항목이 메모의 "지켜야 할 것"에 모두 있는가.
- 메모에 다음 행동이 둘 이상의 안을 나란히 두는가, 전환 조건에 확인 방법이 비었는가, 과정 용어가 남았는가.
- 메모에 근거 ID 패턴이나 좌석 라벨이 남았는가. 확인 명령: `grep -nE '\b[A-Z]{2}-[EX][0-9]+\b|\b(V[0-9]+|[A-Z]{2})\b' memo-seats.md`로 찾고, `ids.md`의 익명 ID와 맞는 것만 센다.

걸린 것이 있으면 같은 Judge에게 그 목록만 보내 1회 고치게 한다. 조정자가 고치지 않는다.
